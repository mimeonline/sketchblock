# Architecture diagram sources

The English C4 system context and runtime building-block diagrams describe the current Sketchblock source. Each `*.semantic.json` file contains roles, directed relationships, and layout parameters without manually assigned coordinates. The checked-in SVG is generated from that source.

The optional generator is the MSYS diagram-engineering Python builder. It is an external authoring tool and is not bundled with Sketchblock. Set `DIAGRAM_ENGINE_DIR` to a compatible installation containing its `scripts` directory. The semantic sources and checked-in SVGs remain readable without that tool.

Generate both views from the repository root:

```sh
DIAGRAM_ENGINE_DIR=/path/to/diagram-engine \
  python3 website/static/img/docs/architecture/regenerate.py
```

The regeneration script builds both semantic sources in a temporary directory, checks the resolved geometry with the showcase profile, and writes the public SVGs. It applies one authoring localization adjustment: the external renderer's exact legend text `Legende` and `Container · Datenbank` becomes `Legend` and `Container · Database`. This changes text only; ports, coordinates, shapes, and routes remain generated by the builder. The installed engine remains unchanged.

A shared `presentation.css` adds the Sketchblock palette, emphasizes the core services, and distinguishes the optional external provider. It is embedded into both standalone SVGs. All positions, ports, shapes, and routes still come from the same validated engine output. People use compact C4 boxes with explicit Person labels.

After localization and theming, the script validates the final public SVGs and records their SHA-256 hashes and validator reports in ignored `.playwright/architecture/` storage. Inspect the generated SVGs in the documentation page, including at narrow viewport widths and through their full-size links. Visual review remains pending until that inspection. Resolved geometry, receipts, and visual QA screenshots stay outside the public assets.

These diagrams use a balanced C4 view: the context diagram groups Sketchblock internals; the container diagram shows six runtime blocks. Startup migration jobs, individual HTTP routes, provider adapter classes, and deployment-specific proxies are described in prose rather than drawn as extra runtime containers. GitHub is marked optional; the database relationships also cover instance board storage and session recovery. Live Yjs synchronization and explicit owner saves are separate relationships.
